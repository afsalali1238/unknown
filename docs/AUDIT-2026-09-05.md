### 2.5 How to reach 9/10 (the hard recommendations)

**A1 — Close the engagement learning loop (P0, product-defining).**  
Persist per-node, per-session engagement as a tiny event log in `store` (all optional/defaulted, like `readNext`):

```ts
// new store slice (all optional, validates old backups)
feedSignals: Record<string, { impressions:number; dwells:number; depthExpands:number;
  saves:number; gotIts:number; shares:number; quizStarts:number; quizPasses:number; lastSeen:number }>
sessionSignals: { seen: string[]; seed:number }
```

- Rank script becomes: `score(n) = 0.35*interest + 0.20*dwell/depth + 0.20*save/share + 0.15*adjacent + 0.10*freshness` — explicitly weighting **saves/shares > dwell > likes** per TikTok bar, not inventing a new scheme. Decay over 7 days (exponential half-life = 7d) so recent taste dominates — mirrors HLR's half-life thinking without needing HLR yet.
- Feed rail events already exist (`Save/Queue/Got it/Quiz/Share/Go deeper`): wire them to `feedSignals` in one commit; no new UI.
- Add **tiered learning**: first impression of an unseen adjacent node gets a *curiosity boost* (+0.15) and is measured on next rebuild — the "few hundred → 10–20×" pattern from TikTok, client-side via local counts, no backend.
- **Metrics:** track per-card `impression → dwell → depth-expand → save/share/quiz-pass` funnel; north-star `depth-expand rate` + `saves per session` already named in spec §9.

**A2 — Split & embed the graph (P0 for perf, P1 for ranking).**  
`nodes.ts` is `17175 lines / ~350 kB gz raw → 1054 kB / 343 kB gz chunk` (verified). That's the *largest* chunk by 3×. Two moves:

1. **Route the split** — keep `nodes` as a thin registry (`id, clusterId, tags, related, year, medium`) for ranking, lazy-import per-cluster bodies (`layer0/1/2, quiz, furtherReading`) on demand. This is exactly the `docs/NODES-SPLIT-DECISION.md` plan still deferred; implement the thin registry now (design already done).
2. **Add embedding similarity for serendipity** — precompute a 384-d MiniLM embedding per node at build (`scripts/embed-nodes.ts`, stored as `nodes-embeddings.json` ~300 kB), score serendipity as `cosine(seedNode, candidate) ∈ [0.2, 0.85]` (near but not same cluster). Replace the missing 25% random with *semantic serendipity* — the bar is "surprise + substance," not noise.

**A3 — Cold-start inference from saves (P0, <1 day).**  
After `readNext` or `bookmarks` reaches 3, infer `interests` as `top 2 tags by count` among saved nodes and offer a one-tap "Add these topics?" chip on the feed empty state — don't auto-mutate `interests`, ask. This captures the FEED-SPEC §5 "after ~5 saves, start weighting toward saved clusters" without violating user agency.

**A4 — Tag-level fatigue & diversity guard (P1).**  
Cap any single tag at **max 3 cards per 10-card window**; cap any single `clusterId` at 2 per window (already 1 back-to-back, extend to 2-in-10). Add a `tagSeen` counter decayed per session — TikTok's "no 2 same sound/creator back-to-back" generalizes to this.

**A5 — Retention-aware injection (P1, the Birdbrain move).**  
Inject `dueCount()` nodes into the feed at **1 per ~8 cards** when `dueCount>0`, labelled "Due for review" with inline `Quiz`. This *is* FEED-SPEC §5 v2, now overdue: it unifies discovery and retention into one surface. Keep it behind `adjacencyShare`-style knob `reviewShare=0.12`.

**A6 — Replace Leitner boxes with FSRS (or HLR-light) (P1/P2).**  
Two options, pick one:

- **FSRS (recommended — drop-in):** add `difficulty, stability, retrievability` per card (3 floats), use open-source `fsrs.js` scheduler with fuzz `0.95–1.05`; optimizer over `review` history. `LEITNER_DAYS` becomes fallback only.
- **HLR-light:** fit per-card `halfLife = 2^(strength) * recency` regression (Settles & Meeder §3) using existing `visited`/`review` timestamps + word-level features (word count + jargon density) — MAE −45% vs boxes, no extra UI.

**A7 — Negative signals & dwell quartiles (P2).**  
Add `dismissHint`/`skip` (fast swipe <500 ms with no dwell) as a weak negative; gate it at `−0.3` so it never buries an idea permanently but does de-prioritize a tag for the session. Measure dwell quartiles (p25/p50/p75 per session length) instead of raw ms — this normalizes for readers who are fast vs slow by nature, as TikTok normalizes for short vs long videos.

**A8 — Harden `buildFeed` correctness (P1, small).**  
- Promote `feedSeen: Set<string>` to persisted session state (or `sessionStorage`) so refresh doesn't re-show card 0.
- Add the spec's `+0.10 freshness nudge` explicitly (today it's a sort tiebreak, not a scored term — rank among visited vs unvisited shifts if you add engagement scores).
- Accommodate the tiny-pool case (`Social Constructs` = 3 nodes) by backfilling with embedding-serendipity rather than thinning to 3 cards.

### 2.6 What remains *correct* and should not be rewritten

The **overall shape** — `queue → interest spine → adjacent` with seeded shuffle, visited-first, cluster spacing — is the right decomposition for an offline, client-side lattice. TikTok's 500-dimension ranker is not the goal; a **12-signal, explainable, user-controllable** ranker that *learns within the session* is. Keep the determinism, keep the paper-tint feed feel, keep the "every swipe is a real idea" invariant.

### 3.3 Sample close-read (30 nodes, across clusters)

**Strong (would survive a Farnam Street reject pile):**

- *Most A-cluster startup nodes + K/L mental-model cores*: layer0 opens with a concrete founder tension or mechanism ("PG argues you should do things that don't scale because…"), layer1 earns the title's claim, quiz distractors map to adjacent misconceptions.

**Typical failure modes (anonymized by pattern, not by dogpiling individual IDs):**

1. **The buried lead** (most of the 105): first sentence 3–5 clauses, 40–80 words, thesis arrives in sentence 3. *Fix:* enforce the 55-word truncation the spec already calls for in the feed card, but *also* rewrite so sentence 1 *is* the hook — truncation is a bandage, not a style.
2. **The meta opener** (6 flagged): "This essay explores…", "In this piece, Naval argues…" — tells the reader it's an essay instead of *being* the idea. *Fix:* delete the frame; start with the claim. Compare Blinkist's blinks: every blink is the idea, not the table of contents.
3. **The thin layer0** (43 nodes <30w): often a thesis-strength summary with no scene or tension — collapses L0/L-thesis into one line. *Fix:* add one concrete sentence (who/when/counter-intuitive fact) before the claim.
4. **The orphan** (101 nodes): technically sound but graph-invisible; the adjacent 15% rule never surfaces them because nothing points at them. *Fix:* per §3.5 B2, require ≥2 incoming `related` per node (validated as a WARN, enforced as a gate for new content).
5. **The single-source node:** 1 `furtherReading`, sometimes `unavailable` — fails the provenance bar the brief sets as the *reason* to archive. *Fix:* see B4.

### 3.5 How to reach 9/10 (editorial program, not one PR)

**B1 — Rewrite the 105 + expand the 43 + trim the 11 (P0, editorial sprint).**  
Targeted passes, not a corpus rewrite:

- **Triage sheet** (generate with `scripts/audit-content.ts --json`): rank the 105 by `firstSentenceChars` desc (G2 733c first), assign 15-per-week to a single editor with the one rule: *delete sentence 1 and see if the piece gets better — if yes, ship the deletion*.
- **Enforce the spec's §12 house style in CI:** fail `audit-content hooks` when `firstSentence > 180c` or opener matches `/^This (essay|piece|article|post)/i` or `layer0Words < 32` (thresholds tuned to current median). This is the same `validate → lint → tsc → test → build` gate that already runs in CI.
- **Feed card is not the fix for a weak hook:** keep the ~55w `feedCardTruncate` for display, but require the editor to *write* the 55w, not truncate into it.

**B2 — Wire the 101 orphans (P0, graph repair).**  
A one-time graph pass + a gate:

- Auto-propose 2 incoming `related` per orphan via **embedding nearest-neighbors** (§2.5 A2) filtered to `cosine ∈ [0.45, 0.80]` and `clusterId != orphan.clusterId` — cross-cluster by preference, same-cluster only if tag overlap ≥2. Human approves, script writes.
- **New WARN → ERROR promotion** in `validate-nodes`: any node with `incomingRelated === 0` fails `--strict` (used in CI for new content), existing orphans grandfathered with a dated allowlist that shrinks each week. This is how the lattice becomes denser without edit wars.
- **Raise mutual edge ratio** from 38% (194/508-ish unique pairs) toward **60%** — mutual `related` is what makes "tap related → land on a node that points back" feel like a neighbourhood, not a footpath.

**B3 — Thesis pass (P1, voice).**  
One-editor pass: thesis ≤ 25 words, no subordinate clause before the verb, no citation in the thesis. Thesis is the card's `aria-labelledby` in the feed (accessibility + editorial share one string — make it count).

**B4 — Provenance repair (P1).**  
- Retry the 143 `unavailable` via `scripts/archive-sources.ts` with alt sources (Wayback → plaintext mirror → curated excerpt with `archive.status="excerpt"` and disclosed word count). Target: **<5% unavailable** (industry bar for "curated not copied" — getAbstract's reliability is what justifies its price).
- Enforce **≥2 `furtherReading` per node** for new clusters (`--strict` gate); retrofit single-sourced nodes by finding the primary source's *reply or rebuttal* — the Shortform move (counter-argument as second source) doubles lattice value for one unit of archival work.

**B5 — Quiz pass (P1, retention science).**  
Audit rubric (apply to any 10% sample each writing cycle):

- Correct option = the idea's *mechanism*; distractors = adjacent misconceptions (not strawmen).
- `explanation` resolves the misconception in 1–2 sentences *and* points to the related node that disambiguates it (e.g. "Not sunk cost — that's K3. This is opportunity cost — L2.").
- Tag each quiz by Bloom level (recall → apply); feed the tag into FSRS difficulty (harder Bloom = higher initial difficulty).

**B6 — Reading-level lint (P1, tooling).**  
Add `scripts/lint-prose.ts` (Flesch-Kincaid + avg sentence length + jargon density against `TAGS` lexicon) and gate new nodes at **grade 8–10, avg sentence ≤ 24w, jargon introduced ≤ once per node**. Current corpus mean is fine; this stops regressions without re-litigating every paragraph.

**B7 — Tag rebalance (P2, algorithm-adjacent).**  
Inverse-frequency weight in `buildFeed` (`weight(tag) = 1 / sqrt(count(tag))`) so `Meaning & Self (83)` doesn't flood `Social Constructs (3)` purely by cardinality — restores the "surprise + substance" promise without retagging everything. Longer term, split `Meaning & Self` into 2–3 child tags (e.g. `Identity & Narrative`, `Meaning & Work`, `Belonging`).

**B8 — Editorial program (P2, process).**  
What the Blinkist/Shortform bar actually is: a **cadence**. Adopt Headway's habit loop + Farnam Street's lattice ethic:

- Weekly "**Lattice Day**": one editor rewrites 10 hooks, wires 10 orphans, archives 10 alt sources — 30 nodes/week = full corpus refreshed in 13 weeks, measured by `audit-content` deltas in CI (trend line published in `docs/CONTENT-HEALTH.md`).

### 4.5 How to reach 9/10 (bounded, shippable)

**C1 — Per-cluster nodes split + route chunking (P0, the big perf win).**  
Implement the deferred `NODES-SPLIT-DECISION` plan:

- Registry: `nodes-registry.ts` (id, clusterId, tags, related, year, medium, thesis, counts) — ~40 kB gz, used for `buildFeed` + `SearchBar` index.
- Bodies: `nodes-A.ts` … `nodes-AL.ts` via `import.meta.glob` / `manualChunks: (id)=> id.includes('src/data/nodes-') ? id.slice(...) : …` — loaded only when a card's layers are expanded or `/node/$id` is visited.
- `vite.config.ts`: extend `manualChunks` beyond `nodes`; split `search` (MiniSearch), `quiz`, `audio`, `dnd-kit` into their own chunks so `index` stays 101 kB gz even as features grow.
- **Expected:** first-meaningful feed load −250 kB gz, LCP −300 ms on 3G, INP flat — the Linear "cold load <2s" bar becomes reachable on a mid-range Android.

**C2 — Close the two AA PARTIALs (P0, <1 day combined).**  
- `2.4.11 Focus Not Obscured`: add `html { scroll-padding-bottom: 72px }` (tab bar height) + `scrollIntoView({block:"nearest"})` on card advance; axe regression test with keyboard-only `Tab` through feed + sheet.
- `2.5.7 Dragging Alternatives`: add `↑ / ↓` buttons to each queue row (visible on `:focus-within`, not just on hover) alongside `@dnd-kit`. Already has `KeyboardSensor`; buttons make the "single-pointer without dragging" AA wording explicitly satisfied.

**C3 — Shortcut help & focus management (P1).**  
- `?` opens a 6-item overlay: `j/k or ↑/↓ next/prev, Space deeper, S save, Q queue, / search, ? help`. `Escape` closes. Announce via `aria-live`.
- After advancing a card, move DOM focus to `feed-card-title-{id}` (already `aria-labelledby` target) — `skim.tsx` does, `index.tsx` should match exactly.

**C4 — Offline polish (P1).**  
- When offline and an `unavailable` archive is tapped, replace the "Unavailable" chip with a **plain-English offline hint** ("Saved for offline — this source wasn't archivable. Try the citation in `furtherReading` or come back online.") — meets the spec §8 offline contract.
- Add `navigator.serviceWorker.ready` → `periodicSync` (where supported) to refresh `nodes-registry` weekly.

**C5 — Per-node SEO/share (P1/P2).**  
- `HeadContent` per `/node/$id`: `title = "{title} — {author} · Unknown"`, `description = thesis (≤155c)`, `og:image` = generated `paper/ink` card (Vercel OG or static template), `og:type=article`, `article:published_time=year`.
- `application/ld+json` `Article` + `BreadcrumbList` (Cluster → Node) and `ItemList` for sitemap clusters — Structured data is how Google surfaces Farnam/Stripe-level sources.
- Ship ` /?start=<id>` share link that seeds the feed with that card first — the spec §7 deep-link.

**C6 — Motion & haptics (P2, taste).**  
- Keep Linear's "<150 ms" rule [Linear breakdown]: feed advance `120ms var(--ease-out)`, dwell-expands `220ms var(--ease-spring)`. No parallax.
- Where supported, `navigator.vibrate(10)` on save/queue — subtle, paper-like feedback without visual noise.

**C7 — Design QA harness (P2, process).**  
- Add `playwright --grep a11y` (axe) to CI alongside `validate → lint → tsc → test → build` (already `lint --max-warnings 10`).
- Add a 320 px reflow + `prefers-reduced-motion` + `prefers-contrast:more` visual regression — these are the WCAG 1.4.10/1.4.12 catches that no linter finds.

## 6. What not to change

Some things are already at or above bar — churn would be anti-improvement:

- **Paper/ink editorial system** — dark-mode token inversion with re-verified contrast is rarer than it looks; keep the constraint, don't add accent hues.
- **Nav discipline (4 tabs)** — the product brief's §5 cut from 6 to 4 is load-bearing for decision paralysis; resist the 5th tab.
- **Offline-first PWA framing** — SW versioning + warmup + stale-while-revalidate is already better than most Start apps; iterate, don't rewrite.
- **Feed determinism per session** — TikTok's backend is not the model; a client-side, explainable, user-controllable feed is the differentiator — just make it *learn*.
