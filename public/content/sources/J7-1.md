A **proximate cause** is what immediately produced an outcome; a **root cause** is the deeper, usually systemic condition that made the proximate cause possible. Treating the proximate cause is treating symptoms: the problem returns in a new form. The Toyota production system encoded this in the **"Five Whys"** — when something goes wrong, ask "why" five times, each answer moving from event to system, until the level where a change prevents an entire class of failures.

Example pattern: a missed deadline → because shipping ran late (proximate) → why? a component arrived late → why? the supplier wasn't double-checked → why? the vendor-selection checklist lacks redundancy → why? procurement optimized for cost over reliability (root). Fixing the root — the incentive and checklist — prevents the next failure, which may arrive through a different supplier entirely.

Why people stop early: proximate causes are visible, assignable to a person, and actionable with blame; root causes are structural, implicate systems (often including leadership), and require harder changes. Politics and time pressure push organizations to announce the near-cause and move on.

Discipline: treat the first explanation as a lead, not an answer; run five-whys without skipping steps; distinguish *causal factors* (many) from the *root cause* (the one whose removal makes the event class unlikely); and in decision-making, work from root causes — fixing goals and incentives — rather than repeatedly patching outputs. The same logic applies personally: repeated similar failures (finances, relationships, projects) almost always share a root one level deeper than the incident.
